## Built (branch `claude/next-steps-discussion-303uz0`, version 0.4.0.0)

The pipeline, left to right:

```
movie feeder (-re, video COPY, audio->AAC 48k) ─┐
                                                ├─► feed.ts ─► LadderEncoder (1 ffmpeg, N rungs) ─► <temp>/MovieNight/ladder/{master.m3u8, v0/, v1/, v2/}
slate feeder (libx264 still + tone, 48k) ───────┘                                                          │
                                                                                                          ▼
                                                        MovieNightTunerHost hands clients  http(s)://<host the client used>/MovieNight/stream/hls/master.m3u8?api_key=<client token>
                                                                                                          │
                                                        LadderStreamController ([Authorize]) serves it, rewriting playlists so api_key rides on every URI
```

| file | what |
|---|---|
| `LadderCommandBuilder.cs` | pure builder for the encoder args: N rungs (720p top, 480p, 360p), backend-specific scale chains and encoders (qsv / vaapi / nvenc / amf / libx264), 4 s segments, 6-segment window, `delete_segments`, mpegts. Unit-tested per backend. |

## Release + install (local session)

1. Merge the branch to `master` (or cherry-pick). `build.yaml` and
   `Directory.Build.props` are already at **0.4.0.0** with the changelog written.
2. Verify the assembly version before packaging (CLAUDE.md gotcha):
   `[System.Reflection.AssemblyName]::GetAssemblyName(dllPath).Version` → 0.4.0.0.
3. `gh release create v0.4.0.0 jellyfin-plugin-movienight_0.4.0.0.zip`, then add the
   version entry to `manifest.json` on master (checksum = md5 of the zip, sourceUrl,
   timestamp). Wait ~60 s for raw.githubusercontent CDN.
4. On the NAS: "Update Plugins" is still broken server-wide → install directly:
   `POST /Packages/Installed/Movie%20Night?version=0.4.0.0` (204), then
   `POST /System/Restart` (~3.5 min). Confirm `Loaded plugin: Movie Night 0.4.0.0`
   in the log; a second restart is sometimes needed.
5. Hard-reload any open Jellyfin Web tab (stale `liveStreamId` gotcha).

Expected startup log lines: `registered M3U tuner`, `registered XMLTV listings
provider`, `removed 1 retired T0 gate tuner entry(ies)` (first boot only),
`registered live tuner host`.

## Step-1 acceptance test (roadmap "done when")

Settings first: rungs = 1, bitrate 4000, public base URL blank. Jellyfin's
hardware acceleration on the NAS is QSV → the encoder uses `h264_qsv` with
`-g 96 -forced_idr 1` (never `-force_key_frames`, per CLAUDE.md).

1. **Go Live from the page** with a short-ish film (no Prepare yet). Expect the
   summary to flip to `Live` within ~10 s; `Encoder: running, 1 rung(s), Qsv`.
   If it fails, the 409 body carries ffmpeg's stderr; also `GET api/live/status`.
2. **Channel appears.** Live TV → channels → "Movie Night" (900). The guide
   refresh is forced on Go Live; if the channel is missing after 30 s, check the
   log for `GetChannels` errors and whether `Refresh Guide` ran.
3. **Tune on Roku, then web (Chrome).** For each, in `GET /Sessions` confirm
   `PlayMethod: DirectPlay`, and in the page's status `Encoder.Fetches.ByRemote`
   should show **the client's own IP** with its player UA (Roku/DVP…). An ffmpeg
   census must show exactly ONE ffmpeg beyond the feeders (the encoder) — no
   per-client process. **This is the T0 result reproduced on the live pipeline.**
   - If the client gets 401s: the token did not reach the segments. Check the
     `media source requested … ladder URL via …` log line — it must end in
     `api_key=…`, and playlists fetched with `?api_key=` must come back rewritten
     (curl `master.m3u8?api_key=<key>` and look at the URI lines).
   - If Jellyfin transcodes instead: `TranscodeReasons` in PlaybackInfo says why.
     `Container="hls"` + absolute URL is the combination that passed T0.
4. **Pause** from the page. Both clients show the slate within ~10–20 s (client
   buffer depth; Jon accepted ~15 s). Status shows `PAUSED`, position frozen.
5. **Resume.** Both clients return to the movie ~10 s before the pause point,
   at the same moment (± their individual lag). T5.
6. **Untune for two minutes, retune.** Lands at the live edge (position ≈
   wall-clock since Go Live), not where you left. This is the sliding window
   doing its job; also the first-ever measurement of live-edge behaviour.
7. **Stop.** Channel disappears from the list within a few seconds; no orphan
   ffmpeg (`ps` for `feed.ts` / `hls`).
8. **Prepare + captions.** Pick a film with an English subtitle track, choose
   it, Prepare. Watch `prepare/status` percent climb (QSV ~2–4× realtime on the
   NAS). Then Go Live: summary says `[prepared mezzanine]`, captions visible on
   the client. Text track first; a PGS track second if one is handy.
9. **Rungs = 2 on the NAS** (settings → save → Go Live). Just confirm the
   encoder keeps up (`speed=` in `Encoder.Stderr` ≥ 1.0x) and Roku plays; a
   rung switch is a bonus, not a gate here.

Then record results in `ITERATION-LOG.md` (new arc) and DECISIONS.md if
anything got ruled.

## What I could not verify from here (highest-risk first)

1. **`api_key` on the ladder URL.** New relative to the T0 gate, which passed
   with a bare URL. The mechanism is exactly Jellyfin's own transcoding-URL
   idiom, but no client has fetched OUR route with it. If a client balks, the
   fallback experiment is a `PublicBaseUrl` pointing at the LAN IP (rules out
   host derivation) — and if it is the auth itself, say so before removing it;
   anonymous was only ever acceptable for the spike.
2. **Claim name `Jellyfin-Token`.** If the media-source log line says
   `NO TOKEN`, the claim name is wrong for this server version. It comes from
   `Jellyfin.Api.Constants.InternalClaimTypes.Token`; check
   `/api-docs/openapi.json` or the server source for 10.11.6.
3. **EPG for a tuner-host channel.** Channel id is `movienight`, the same id the
   XMLTV endpoint has always emitted, so the existing listings provider should
   attach — but the T0 channel never had listings and nobody looked. Roku shows
   "no schedule information" if this does not line up; not a blocker for
   playback.
4. **The seam through a re-encode with a COPIED feeder.** v3's proven seam ran
   feeder-encode → copy remux. Now it is copy feeder → encode: the encoder sees
   a resolution/fps change at every slate swap (1080p24 film → 720p30 slate) and
   must reinit its filter graph. Expected to work (ffmpeg does this by default;
   v0.3.25 re-encoded across seams fine) but it is the change most likely to
   produce a new failure mode. Watch the encoder stderr at the first pause.
5. **Software decode cost without a mezzanine.** A 1080p h264 remux decodes in
   software inside the encoder (~1 core). Fine on the NAS. A 4K HEVC source will
   not keep up without Prepare — the log warns at Go Live.
6. **Encoder crash-restart** resets segment numbering (clients see media
   sequence go backwards). Untested; a retune fixes it. Better handling is V2.
7. **Windows paths / process handling** — nothing here is Linux-specific by
   inspection (no tmpfs, no signals on the new path), but it has never run there.

## Knobs while testing

- **`POST /MovieNight/api/debug/live/source?container=&directPlay=&directStream=&supportsTranscoding=&anonymousRoute=&baseUrl=`**
  (all optional; `GET` shows current) — the T0-style knobs for the live tuner
  host, in memory, no restart. Defaults: `hls` / true / true / true / false /
  none. Two experiments they are for: **`supportsTranscoding=false`** (the exact
  T0-passing combination, if a client that direct-played in T0 now takes the
  hop), and **`anonymousRoute=true`** (hands out a token-less
  `stream/hls-open/master.m3u8` URL and opens that route: if the client plays
  that but not the authed URL, the `api_key` is the problem, not the ladder).
  Turn `anonymousRoute` back off afterwards. A tune AFTER changing a knob is
  needed — the fields are read per PlaybackInfo.

- `GET /MovieNight/api/live/status` — everything: session, feed (position,
  paused, feeder/slate alive), encoder (pid, rungs, segments on disk, fetches
  by remote, stderr).
- `GET /MovieNight/api/prepare/status`, `POST …/prepare/cancel`.
- `POST /MovieNight/api/debug/encode-probe` still exists for arbitrary ffmpeg
  experiments (e.g. `h264_nvenc` on the friend's rig before trusting it).
- Settings changes take effect at the next Go Live (rungs, bitrate) or the next
  PlaybackInfo (base URL, channel name/number after a guide refresh).
