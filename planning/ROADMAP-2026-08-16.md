# Roadmap — from proven v3 to usable (ruled by Jon, 2026-08-16)

Context: the v0.3.28 switcher-v3 acceptance test PASSED (see ITERATION-LOG
arc 6) — universal pause/resume works across Web + Roku. This roadmap is the
agreed path from "proven in a test rig" to "usable for a real movie night."
Jon's ruling 2026-08-16: all four steps, in this order.

## 1. Rewire config page to v3 — `DONE (v0.3.29/0.3.30, verified 2026-08-16 mini-soak)`

The dashboard config page's Go Live / Pause-Resume / Stop buttons and status
readout drive the v3 pipeline (`sw2/*` endpoints) instead of the old HLS
path. Item-ID paste box stays for now.

**Done when:** a full golive → pause → resume → stop cycle runs entirely
from the dashboard page (phone browser counts), no curl involved.

## 1b. Zero-viewer feeder fix (v0.3.31) — `ruled 2026-08-16 evening, ship before the Tuesday soak`

Found in the 2026-08-16 mini-soak (W13 S3E7): when the last viewer
disconnects, the feeder blocks on its full stdout pipe while wall-clock
position keeps advancing; on the next tune, -re "catch-up" bursts ~3x
realtime (heartbeat evidence: 12.7 Mbps) and the rejoining client's playhead
lands the whole gap-length behind live - every admin action then reaches
screens that many minutes late (measured: stable ~1:50 echo for a ~2min
gap). Fix: when the feed.ts consumer disconnects, kill the feeder and mark
the session feeder-pending at the current wall position; the existing
lazy-start respawns it at the live edge on the next consumer.

**Done when:** tune → untune ~2min → retune shows the live position, no
bitrate burst in the heartbeats, and a pause reaches the rejoined client in
normal (~15-30s) client-buffer time.

## 5. Captions spike: CC1 embedding vs burn-in — `backlog (Jon, 2026-08-16)`

Today the feeder strips all subtitle tracks - clients have no CC option.
Two candidate designs, in preference order:

- **CC1/EIA-608 embedding** (preferred if viable): captions live in H.264
  SEI side-data, so they survive the -c copy remuxer and Jellyfin's remux
  untouched, and viewers keep a per-client CC toggle (the broadcast-TV
  model). ffmpeg can pass A53 data through but cannot author it from an
  SRT - needs an external injection stage (libcaption or similar). Spike
  question 1, cheap: does A53 survive our exact pipeline (h264_qsv →
  copy remux → Jellyfin remux → Roku with CC on)? One encode-probe with an
  A53-bearing sample + one tuned client answers it, and gates everything
  else.
- **Burn-in fallback**: subtitles filter in the feeder before hwupload,
  host picks a track at Go Live. One evening of work, works on every
  client, but all-or-nothing for the whole room.

**Done when:** the spike verdict is recorded (CC1 viable or not) and
whichever design won is ruled by Jon for a build slot.
