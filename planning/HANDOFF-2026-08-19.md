## The one decision blocking M1

**Segment format: mpegts or fmp4?** It must be settled BEFORE the mezzanine is
built, because the mezzanine IS rung 0 (`-c copy`) and has to be produced in the
chosen format — rebuilding a feature-length mezzanine is expensive (§10.3).

What is known:
- fmp4 costs **nothing** on the encoder side — it was at least as fast as mpegts
  in every paired run (~2.53x vs ~1.89x mean). The earlier "fmp4 is 2.7x slower"
  reading was a loaded box and is wrong.
- fmp4 preserves GOP alignment identically (verified).
- fmp4 is the format most likely to fix **Firefox**, and possibly ExoPlayer
  (androidtv #5237's stated trigger is MPEG-TS).
- **But no client has ever played an fmp4 ladder.** Roku, Xbox and Chrome all
  passed on **mpegts**. Switching format could lose a client that currently works.

**Do this first (~1 small release + 4 tunes):**
1. Add a `segmentType` knob to `T0Gate.BuildLadderAsync` + the `t0/source`
   endpoint (mpegts | fmp4).
2. Extend the ladder route whitelist to allow `init_<digits>.mp4` and
   `seg_<digits>.m4s` — fmp4 emits `#EXT-X-MAP:URI="init_1.mp4"` per variant and
   the current whitelist 404s it.
3. Rebuild the ladder as fmp4, then tune **Roku, Xbox, Chrome, Firefox**. Roku and
   Xbox are the ones that must not regress; Firefox is the one that might flip.
4. Whichever format wins, record it in DECISIONS.md, then start M1.

## Then, in order

- **M1 — mezzanine prep.** One-off pre-encode of the film: 1080p ~6 Mbps h264 +
  AAC with a **fixed closed GOP matching the ladder** (`-g 96 -forced_idr 1`).
  T2 demonstrated why this is mandatory: `-c copy` from an arbitrary movie gives
  ragged segments (1.681–4.463s) and 0.22s drift. Done when rung 0's durations
  match rungs 1 and 2 exactly.
- **M3 — authed segment route** (parallel with M1). Replace the spike's anonymous
  route with `[Authorize]`; keep the exact-name whitelist.
- **M2 — ladder encoder + sliding window** → T3. This is where the live edge
  becomes real and testable for the first time (`-hls_list_size 6`,
  `delete_segments`, no ENDLIST). Nothing measured so far says ANYTHING about
  live-edge behaviour — the T0 ladder is VOD with an ENDLIST.
- **M4 — real tuner host on the live pipeline** → T4, T5.
- **M5–M7** — live-edge/ABR, scale/soak, then delete the superseded HLS machinery.

## Open items that need Jon, not an implementer

1. **Captions are a V1 requirement** (Jon, 2026-08-19) and the design does not
   mention them at all. WebVTT-over-HLS is the ecosystem's supported path, which
   means an `#EXT-X-MEDIA:TYPE=SUBTITLES` rendition alongside the video rungs —
   touching both the ladder encoder and the mezzanine. Cheap designed in, expensive
   bolted on. **Also:** Swiftfin's Native/AVPlayer has no subtitle-track selection,
   so Apple clients may need the VLCKit player for captions — a UX/doc decision.
2. **`DESIGN-abr-ladder.md` needs amending.** §4(G) names the wrong load-bearing
   field (it is `Container`, not `SupportsTranscoding`); §4(D) picks `mpegts`
   without considering clients; per-client URL derivation is in no milestone.
   Amending a ruled design is Jon's call.
3. **Per-client URL derivation is unbuilt and required.** The gate passed with a
   hardcoded LAN base URL (`http://192.168.68.118:8096`). Remote viewers over
   tailscale will not reach that. M4 must derive a per-client address
   (`GetSmartApiUrl`), not hold a constant.
4. **Android phone app: Jon said ignore for now.** It cannot direct-play any
   adaptive stream — its profile lists only progressive containers, no HLS, no
   DASH. Not fixable server-side. Workaround if it ever matters: use Chrome on the
   phone.

## Environment notes for the next session

- **Jellyfin API from the laptop works** — `http://nas.tailb1a3d2.ts.net:8096`
  with `X-Emby-Token`. An API key is needed; ask Jon.
- **"Update Plugins" is broken server-wide on this NAS** (unrelated plugin holds a
  lock on `Jellyfin Tweaks_4.0.0.0/thumb.png`, which aborts the whole package
  scan). Install with `POST /Packages/Installed/{name}?version=X.Y.Z.W` then
  `POST /System/Restart`. Restart takes ~3.5 minutes on this box.
- **Runtime knobs reset on restart** — `t0/source` settings are in-memory. After
  any restart, re-set `baseUrl` (it falls back to relative, which is the broken case).
- **The T0 ladder currently holds 90s of The Dressmaker**, not the synthetic test
  pattern — the T2 probes wrote there because it is the only path the serving route
  exposes. `POST t0/build-ladder` rebuilds the synthetic one (~45s).
- **Do not trust an ffmpeg process census as the instrument.** Jellyfin remuxes
  with `-readrate 10`, races through a VOD ladder in ~30s and exits, so a late
  census reads 0 whether or not a hop happened. Use `PlayMethod` from `/Sessions`
  plus the **User-Agent** in `t0/status` — and note a browser reaching us through
  the tailscale HTTPS proxy arrives wearing the NAS's own IP, so IP alone cannot
  distinguish browser-direct from server-side ffmpeg.
- **NAS health:** the `velocity-dashboard` container's streamlit process leaks
  zombie children (~50/day; hit 2533 with the box at 64% iowait before it was
